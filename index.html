Lumo PoC — vaadin-role~="…" marker selectors

Light-DOM Lumo (from proto/lumo-light-dom) with tag-name selectors replaced by a component-stamped vaadin marker attribute. One theme selector now covers the component, any subclass under any tag name (#7055), and plain HTML elements that opt in manually (#1803).

"Wipe" simulates a framework/user overwriting class (className=, class=${'…'}, utility classes). With class-based markers (.v-button) everything would lose its styles; the attribute marker survives — nothing changes.

5. Role tokens: vaadin-role="text-field field input"

The original theme keeps 16-tag and 10-tag selector lists in field.css / input-container.css. Here text-field and text-area stamp the field and input role tokens, and the shared files contain zero tag names — new field components join the family without editing the theme.

Open DevTools: components carry e.g. vaadin-role="text-field field input" stamped at upgrade (PoC: src/marker-stamp.js; natively one line in a base mixin's connectedCallback). User-authored tokens are merged, never clobbered.
